# ADR-001: フレームワークに Spring Boot を採用する

## ステータス
採用（Accepted） - 2026-01

## コンテキスト
本プロジェクトは、認証・認可を含むチーム向けタスク管理 Web アプリケーションであり、以下の要件を満たすフレームワークが必要である。

- サーバーサイドレンダリング（SSR）に対応していること
- 認証・認可のフレームワークが充実していること
- DB マイグレーションやバリデーションのエコシステムが豊富であること
- 日本語の学習リソースが充実していること

## 検討した選択肢

### 1. Spring Boot (Java)
- ✅ Spring Security による強力な認証・認可機能
- ✅ Flyway / MyBatis / Bean Validation 等のエコシステムが豊富
- ✅ 日本のエンタープライズ開発で広く採用（就職に有利）
- ✅ Thymeleaf によるサーバーサイドレンダリングの仕組みが整備
- ⚠️ 学習コストが比較的高い

### 2. Express.js (Node.js)
- ✅ 軽量で立ち上がりが早い
- ✅ フロントエンドと言語を統一できる（JavaScript）
- ⚠️ 認証・認可は Passport.js 等の外部ライブラリに依存
- ⚠️ 大規模アプリケーションでの構造化が難しい

### 3. Laravel (PHP)
- ✅ 学習コストが低い
- ✅ 認証機能（Breeze / Jetstream）が組み込み
- ⚠️ Java に比べて型安全性が低い
- ⚠️ 日本のサーバーサイド市場では Java の需要が依然として高い

## 決定
**Spring Boot** を採用する。

認証・認可の要件が本プロジェクトの中核であり、Spring Security の成熟度と柔軟性が最も適していると判断した。また、ポートフォリオとしての市場価値を考慮した場合、日本のエンタープライズ市場で広く採用されている Java / Spring Boot のスキルを証明できる点も重要な要因である。

## 結果
- Spring Security によるロールベースアクセス制御を実装できた
- `@PreAuthorize` とカスタム権限判定クラスの組み合わせによる TODO 単位のきめ細かな権限制御を実現できた
- Flyway + MyBatis + Bean Validation の組み合わせにより、保守性の高い構成を実現できた
