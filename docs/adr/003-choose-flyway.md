# ADR-003: DB マイグレーションに Flyway を採用する

## ステータス
採用（Accepted） - 2026-01

## コンテキスト
本プロジェクトでは、データベーススキーマの変更をバージョン管理し、環境間で一貫した状態を保つ必要がある。

## 検討した選択肢

### 1. Flyway
- ✅ SQL ベースのマイグレーション（習得コストが低い）
- ✅ Spring Boot との統合が容易（starter が用意されている）
- ✅ バージョン番号（V1.0.0__）による明確な適用順序管理
- ✅ 繰り返し実行マイグレーション（R__）によるサンプルデータ管理が可能
- ⚠️ ロールバック機能は有償版のみ

### 2. Liquibase
- ✅ XML / YAML / JSON / SQL の複数形式に対応
- ✅ ロールバック機能が無償版でも利用可能
- ⚠️ 設定が Flyway に比べて複雑
- ⚠️ Spring Boot での利用例は Flyway より少ない

### 3. 手動管理（SQL スクリプトの手動実行）
- ✅ 学習コストがゼロ
- ⚠️ 環境間でスキーマが不整合になるリスクが高い
- ⚠️ チーム開発では管理が破綻しやすい

## 決定
**Flyway** を採用する。

Spring Boot との統合のシンプルさと、SQL ベースのマイグレーションによる学習コストの低さが決め手となった。また、繰り返し実行マイグレーション（R__）機能により、開発中のサンプルデータ管理が効率化できる点も評価した。

## 結果
- `V1.0.0__create_tables.sql` でテーブル作成を、`R__insert_sample_data.sql` でサンプルデータ投入を管理
- アプリケーション起動時に自動でマイグレーションが適用され、手動でのDB操作が不要に
- チーム開発でも同一のスキーマ状態を再現できる基盤を構築できた
