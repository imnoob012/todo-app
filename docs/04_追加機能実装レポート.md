# 追加機能・セキュリティ改善 実装レポート

## 1. 実装の目的

この修正では、TODO 管理アプリを「動く CRUD」から「実務で説明しやすい業務アプリ」に近づけることを目的にしました。

主に次の観点を強化しています。

- 認可: 画面操作だけでなく、直接 POST されても権限外操作を防ぐ
- 情報漏えい対策: API レスポンスからパスワードハッシュを除外する
- XSS 対策: JavaScript でユーザー入力値を HTML として描画しない
- データ整合性: username / email の重複を DB とアプリの両方で防ぐ
- 業務機能: 進捗、コメント、変更履歴、ダッシュボードを追加する
- 運用性: Docker Compose で PostgreSQL 込みの起動手順を整える
- テスト: 重要な認可と API レスポンスを MockMvc で確認する

## 2. セキュリティ改善

### メンバー操作を ADMIN のみに制限

対象:

- `MemberViewController`
- `member-detail.html`
- `members.html`

修正内容:

- `/members/add`
- `/members/edit/{id}`
- `/members/update/{id}`
- `/members/delete/{id}`

上記に `@PreAuthorize("hasAuthority('ADMIN')")` を追加しました。

これにより、MEMBER や TODO_ADMIN が URL を直接指定したり、POST リクエストを手作りして送っても、サーバー側で 403 Forbidden になります。

ポイント:

画面のボタンを非表示にするだけではセキュリティ対策になりません。ブラウザの開発者ツールや curl で直接リクエストできるため、重要な権限チェックは必ずサーバー側に置きます。

### API から password を返さない

対象:

- `MemberResponseDto`
- `MemberService`
- `MemberMapper.xml`
- `members.html`
- `member-list.js`
- `member-detail.html`

修正内容:

- `MemberResponseDto` から `password` フィールドを削除
- メンバー一覧 API `/api/members` のレスポンスにパスワードハッシュが含まれないよう修正
- 画面上のパスワード列も削除

ポイント:

パスワードは BCrypt でハッシュ化されていても、外部へ返す必要はありません。必要のない情報は DTO に載せない方が安全です。

### 一覧再描画の XSS 対策

対象:

- `todo-list.js`
- `member-list.js`

修正内容:

- `row.innerHTML = ...` を廃止
- `document.createElement()` と `textContent` でセルを作る方式に変更

ポイント:

`innerHTML` にユーザー入力値を入れると、保存された `<script>` やイベント属性が HTML として解釈される可能性があります。`textContent` は文字列として扱うため、XSS 対策として安全です。

### username / email の重複防止

対象:

- `V1.1.0__add_status_comments_history_and_constraints.sql`
- `MemberMapper`
- `MemberService`
- `MemberViewController`

修正内容:

- PostgreSQL の partial unique index を追加
- `deleted_flg = FALSE` の有効ユーザーだけ username / email を一意に制約
- 登録・更新フォームでは重複時に入力エラーとして表示

ポイント:

論理削除を採用しているため、通常の UNIQUE 制約だけだと削除済みユーザーの username / email まで再利用できなくなります。そこで `WHERE deleted_flg = FALSE` の partial unique index にしています。

## 3. TODO 進捗管理

対象:

- `TodoStatus`
- `Todo`
- `TodoForm`
- `TodoResponseDto`
- `TodoMapper.xml`
- `todos.html`
- `todo-form.html`
- `todo-edit.html`
- `todo-detail.html`

追加内容:

- TODO / IN_PROGRESS / DONE のステータスを追加
- DONE になったタイミングで `completed_at` を自動設定
- DONE から別ステータスに戻した場合は `completed_at` をクリア
- 一覧、検索、登録、編集、詳細画面にステータスを表示

ポイント:

ステータスは文字列ではなく enum にしました。画面表示用のラベルと DB 保存値を分けられるため、表示名を変えても DB の値は安定します。

## 4. コメント・変更履歴

対象:

- `todo_comments`
- `todo_histories`
- `TodoComment`
- `TodoHistory`
- `TodoService`
- `TodoMapper.xml`
- `todo-detail.html`

追加内容:

- TODO 詳細画面でコメントを追加できるようにしました
- TODO の更新時に、変更された項目だけ履歴に残します
- 履歴対象は TODO名、優先度、期限、分類、ステータス、内容、担当者です
- コメント追加、TODO登録、TODO削除も履歴に残します

ポイント:

実務では「今の値」だけでなく、「誰がいつ何を変えたか」が重要になります。変更履歴を持つことで、問い合わせ対応や監査に強い設計になります。

## 5. ダッシュボード

対象:

- `DashboardViewController`
- `DashboardService`
- `DashboardMapper`
- `DashboardMapper.xml`
- `dashboard.html`
- `dashboard.css`

追加内容:

- 総 TODO 数
- 期限切れ TODO 数
- 今週期限 TODO 数
- 進行中 TODO 数
- 完了 TODO 数
- 完了率
- ステータス別件数
- 担当者別件数
- 優先度別件数
- 分類別件数

ポイント:

集計は SQL 側で行っています。Java で全件取得してから集計するより、DB の得意分野を活かせます。件数が増えた場合にも説明しやすい設計です。

## 6. Docker Compose 対応

対象:

- `Dockerfile`
- `docker-compose.yml`
- `.dockerignore`
- `application.properties`

追加内容:

- PostgreSQL 16 とアプリを Docker Compose で起動
- DB の healthcheck 後にアプリを起動
- DB 接続情報を環境変数で上書き可能に変更

起動コマンド:

```bash
docker compose up --build
```

起動後:

```text
http://localhost:8080/login
```

## 7. テスト追加

対象:

- `MemberViewControllerSecurityTest`
- `MemberApiControllerTest`
- `TodoAppApplicationTests`

追加内容:

- MEMBER 権限ではメンバー登録画面を開けないこと
- MEMBER 権限ではメンバー登録 POST が 403 になること
- MEMBER 権限ではメンバー更新 POST が 403 になること
- MEMBER 権限ではメンバー削除 POST が 403 になること
- `/api/members` に password が含まれないこと

ポイント:

テストは「壊れたら困る仕様」から優先して書いています。今回はレビューで High 指摘だった認可と情報漏えいを中心にしました。
